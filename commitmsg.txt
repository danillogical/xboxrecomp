Give the NV2A a display clock and a real interrupt line

The card had no interrupt source. The kernel's synthetic vblank asserted
vblank by OR-ing into the aperture:

    MEM32(0xFD060100) |= 1;          /* NV_PCRTC_INTR_0 */
    MEM32(0xFD000100) |= (1 << 24);  /* NV_PMC_INTR_0  */

Both registers are write-1-to-clear in the model, as they are on the card,
so an OR against the read-back value CLEARS every bit already pending and
sets nothing. Measured: with that path enabled the guest ISR ran and queued
a DPC 968 times, while the published model snapshot read NV_PMC_INTR_0 = 0
and NV_PCRTC_INTR_0 = 0, and the DPC routine's `test esi, 0x01000000` never
took its branch -- so the producer that signals the title's frame event was
never reached (logs/runs/20260922-155540-785-a2-vblank-probe).

What is added:
- `nv2a_vblank_pulse` asserts the PCRTC pending bit from the model's display
  clock. The source is unconditional; the guest's own write-1-to-clear is the
  only acknowledgment.
- `nv2a_display_frame_ns` derives the frame period from the guest-programmed
  video PLL and flat-panel timing, falling back to 60 Hz and reporting which
  it used.
- `pci_irq_assert`/`deassert` were no-op stubs, so the model aggregated its
  masks and told nobody. `nv2a_set_irq_sink` routes the line to a host owner,
  reported on transitions only -- a level that stays asserted must not
  re-enter the guest ISR.
- The standalone service thread drives the display clock and never sleeps a
  zero-length wait, which would spin between frames.
- `NV_PCRTC_INTR_EN_0` joins the published diagnostic snapshot.

`nv2a_irq_line_asserted` keeps the upstream `pending && enabled` condition:
NV_PMC_INTR_EN_0 is a two-bit hardware/software master enable, not a
per-source mask, so a per-source AND against it is wrong.
